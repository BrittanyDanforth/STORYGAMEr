# NPC conversation and standalone key-storage correction

This increment responds to two observed problems: the user reports that AI replies work but sound generic and fail to react naturally to insults, and an additional standalone Settings check found that remembering a key fails before a connection request begins. The corrected Linux player now passes remembering, restarting with and removing a fabricated key. Final dialogue source is `npc-key-r2`; live dialogue-quality evaluation remains separate from the source/Editor and native UI checks below. The full 320-feature plan remains incomplete.

## Remembered-key failure and replacement

The additional Linux test of `ui-menu-r2` (the source of the earlier UI r3 delivery) explicitly selected **Save key in UserData folder**, then pressed **Connect** using fabricated input. The player threw `ConfigurationErrorsException` inside `DataContractJsonSerializer.WriteObject`. No settings file was written, no connection request started and no visible error was presented. Restart/removal could not be tested because no key was saved. [The failed run](../Validation/NPCDialogueUpdate/HistoricalRememberFailure/acceptance-r2-settings.json), five masked/empty captures and the log are retained. This is an observed Linux standalone failure; Windows was not run to establish the defect's platform scope.

The earlier 13 Unity Editor and 173 portable key-store assertions did not exercise that standalone configuration dependency. Their recorded results remain historical evidence and do not prove remembered-key behavior in the shipped player.

`SignalDebtApiKeyStore` now uses a small pure-C# JSON reader/writer for the existing schema-one settings file. It removes the DataContract/configuration dependency, requires the complete two-field document, rejects duplicate/unknown fields and trailing data, validates UTF-8, and retains the bounded file/key sizes. Session precedence, explicit plaintext remember, atomic replacement, Unix file permissions and the public Settings API are unchanged. **220 portable assertions across 13 cases** pass, including the earlier 173 assertions and added parser/size/dependency checks. Thirteen fresh Unity Editor assertions also pass with the replacement codec. The [corrected npc-key-r1 native run](../Validation/NPCDialogueUpdate/NativeKeyR1/acceptance-npc-key-r1.json) separately passed **11 checks with eight captures and three clean exits**. Explicit Remember wrote schema-one settings with Unix mode 0600, cleared the masked input and showed Saved in UserData. Restart preserved the file bytes/time and showed saved status with a blank field; Remove deleted the file and showed No key set. Settings alone created no campaign. One fabricated invalid-key Connect displayed the friendly authentication error; raw HTTP headers/body were not collected, and no successful generated reply was tested. The key-store source is byte-identical in r2; r1 remains the exact player tested for this detailed regression.

## Conversation context and authored personality

The current copy-shop contact now has an authored temperament, ordinary interests, concerns and stage-specific activity. The profile gives the worker a reason to care about the order queue, being treated competently, their bicycle and a cheap meal after work. Provider instructions ask for a proportionate response to the latest message's social meaning: insults, jokes, apologies, questions and pressure should influence the reply instead of routinely producing a work-status recap. This describes the supplied context and intended behavior; a prompt change is not proof that generated replies meet it.

Requests include up to **12 recent visible conversation lines**, each bounded to 1,000 characters. Authored Southbank messages and player messages can enter that history; technical/private Notice lines are omitted, and the current player message is not duplicated. This history belongs to the current UI session. It is not saved social memory, a persistent relationship, a trust meter or a remembered feud after restarting the game.

The final r2 instructions allow a person to trust an ordinary plausible remark, doubt it, misunderstand or suspect wrongdoing according to personality, history, attention and stakes. Proof is not required for every conversational claim. Those fallible beliefs remain separate from verified world state: the character cannot pretend to witness an unseen act, and an earlier successful test establishes only what was observed then. A scam taunt can provoke a personal reaction without creating an authoritative crime or equipment failure. Earlier model text also cannot create a world fact. Payment, inventory and other consequential changes remain rule-controlled saved actions. This follows the master plan's distinction between [personal belief and verified events](Source/master_content.md#what-a-person-actually-knows); it does not implement a durable belief model.

`SignalDebtNpcCharacter` also defines Jon and Mara profiles for future callers. Those definitions do not add actors, schedules, shop encounters, autonomous work or persistent relationships. Only the existing copy-shop conversation is wired into this increment.
