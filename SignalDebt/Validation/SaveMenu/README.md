# Save/load browser and manual checkpoints

The main menu now has **Load Game**; Pause has **Save / Load**. The browser shows three saves per page with day, credits, job progress and local save time. Manual checkpoints may have a name. Current progress, New Game archives and an earlier installation can be selected without editing files. Loading preserves the current campaign in a recovery checkpoint before replacing the active save; failed or stale selections leave the session intact. Checkpoints and archives are retained, and AI settings are separate.

Genuine Unity 6000.0.62f1 checks passed **664 assertions**: [178 across 28 save-library cases](save-library.json), [358 across 51 save-store cases](save-store.json), and [128 across seven conversation groups](conversation.json). These cover immutable checkpoints, independent activation, recovery snapshots, schema migration, stale/invalid selections and filesystem failures. UI behavior is validated separately. No API credential or provider call was used.

To run the new suite with that Unity editor, use `-batchmode -nographics -quit -projectPath <UnityProject> -executeMethod SignalDebt.Editor.SignalDebtSaveLibraryChecks.RunBatch -signalDebtSaveLibraryReport <report.json>`. The fixture uses temporary directories and never reads a player's campaign or API key.

The [r1 native report](native-functional-r1.json) records actual X11 mouse/keyboard input into the uninstrumented Linux standalone at 1200×800. It covers creating a named checkpoint, canceling a load, loading while seated, a correct rebuilt laptop display, safety snapshots, pagination, stale-selection rejection and Refresh, failed-write preservation, New Game archival and restoring that previous campaign. The earlier campaign's saved bytes and existing checkpoints survived New Game. All 116 runtime files stayed unchanged and the player exited 0.

The paid-proof check imports a prior synthetic native-play campaign, then loads it through this browser. The [restored workspace](Screenshots/paid-proof-restored-r1.png) is read-only at 360 credits; clicking payment again changes no saved bytes. This is a restore regression, not a fresh end-to-end proof playthrough. A corrupt archived primary with a valid backup also loads, labels the [recovered backup](Screenshots/recovered-backup-r1.png), uses the selected backup's timestamp and leaves both archive files untouched.

R1 exposed two presentation defects: a listing error hid the explicit checkpoint-write failure, and long names were silently clipped. The [final r2 native acceptance](native-targeted-r2.json) passed both fixes: [64 wide characters](Screenshots/long-name-card-r2.png) display with ellipsis while [confirmation details](Screenshots/long-name-confirm-r2.png) retain separate rows; full names remain stored. A blocked write shows the [explicit failure](Screenshots/explicit-failure-r2.png), preserves the name and active save, and [retry creates exactly one checkpoint](Screenshots/retry-success-r2.png). Continue restores the earlier paid campaign byte-for-byte; its [read-only laptop workspace](Screenshots/paid-restart-r2.png) and disabled payment survive the restart. The player exited 0 with all 116 release files unchanged and no detected runtime exceptions.

Only `SignalDebtSaveMenu.cs` changed between the 185-file r1/r2 snapshots. [Dependency hashes](retained-suite-applicability.json) justify retaining the 664 assertions; the suites were **not rerun** for these two presentation fixes. Both final Linux and Windows builds exited 0 without C# errors. The Windows output contains 134 files and has not been executed here. Selected r1 captures also show the [named checkpoint](Screenshots/named-checkpoint-r1.png), [restored laptop](Screenshots/restored-laptop-r1.png), [pagination](Screenshots/pagination-r1.png) and [previous campaign](Screenshots/previous-campaign-r1.png). Source manifests bind each tested revision; r1 results do not imply a complete replay on r2.

No player files, UserData, campaign fixtures, credentials or large logs belong in this evidence directory. Linux runs use software rendering without an audio device. Windows execution, audio, target-hardware performance, live dialogue and the other AI's neighborhood work are outside this acceptance. This is a partial F191 increment, not completion of the master plan.
