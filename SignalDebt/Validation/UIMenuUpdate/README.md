# Menu and local-data validation evidence

This folder retains bounded evidence for the [menu/laptop update](../../Documentation/UI_Menu_Update.md). It does not certify the completed 320-feature game. The native evidence separates **frozen `ui-menu-r1` broad checks** from the **final `ui-menu-r2` targeted follow-up** after the Bootstrap/menu lifecycle fixes. Both final r2 Windows/Linux builds passed. The r1 matrix was not rerun in full on r2.

| Evidence | Result and scope |
| --- | --- |
| [Provider contract checks](ai-provider-check-result.json) | **73 assertions / 6 groups passed in Unity 6000.0.62f1.** Synthetic payload and strict response-validation fixtures; no credential lookup, provider network call, HTTP transport, cancellation, quota accounting or live NPC acceptance. |
| [Unity key-store checks](ai-key-store-check-result.json) | **13 assertions passed in real Unity Mono**, using its DataContract serializer and an isolated filesystem with fabricated keys. Covers session-only entry, remember/reload, replacement and removal. No real credential or paid request was used. |
| [Isolated key-store checks](api-key-store-isolated-result.json) | **173 assertions / 11 cases passed under .NET 8**, including malformed files, failed writes, precedence and accurate active-key persistence status. This is separate portable filesystem evidence, not a Unity player or Windows test. |
| [Frozen r1 Linux build](linux-ui-menu-r1-build-result.json) | Unity's Linux x64 Mono build exited zero; compilation/build evidence alone does not establish gameplay acceptance. |
| [Frozen r1 native acceptance](NativeR1/acceptance-r1.json) | **20 checks passed, 30 captures, four player exits with code zero.** Real uninstrumented Linux player, native keyboard/mouse input, 1200×800 framebuffer capture and llvmpipe software rendering. |
| [Final r2 Windows build](windows-ui-menu-r2-build-result.json) and [Linux build](linux-ui-menu-r2-build-result.json) | Both Unity Mono builds exited zero from the same [frozen r2 source](ui-menu-r2-source-manifest.json), with no source changes/additions during either build. Native r2 checks are recorded separately below; no Windows execution is claimed. |
| [Final r2 native acceptance](NativeR2/acceptance-r2.json) | **13 targeted checks passed, 23 captures, two player exits with code zero.** Runtime assembly and 161 unchanged production-file hashes match the final r2 Linux build. No full repetition of r1's payment/archive/malformed/future-save matrix. |

The native sequence covers the cold main menu, empty/masked Settings and invalid input, starting/continuing a campaign, the physical laptop and compact apps, repair payment, rent, Pause/Settings/Resume, standing up, restart persistence, New Game archive/cancel behavior, and malformed/future-save preservation. It used invalid dummy input only and created no `ai-settings.json`. Existing-key exclusion from campaign archives is not established by these native cases.

The targeted r2 sequence verifies confirmed mid-seating interruption and reentry, missing-key Send without changing save bytes, usable repair afterward, repeated Pause/Settings/Resume, current New Game confirmation, old AppData schema-one import into local schema-two saves with original/copy bytes and modification times preserved, and readable History/receipts/detail with 150 credits and 400 rent intact. [The r2 report](NativeR2/acceptance-r2.json) identifies two early captures as ambiguous/nonproof: `02-before-seating-interruption.png` and `07-inbox.png`. The confirmed transition is capture 04 with its retained timing JSON; actual Inbox/missing-key evidence is captures 09–10. Direct component disable/re-enable injection and callback-race scenarios were not exercised.

The provider and key-store source hashes matched their respective current production files when this evidence was retained. Their manifests describe the exact compile context; they do not mean every surrounding game file is unchanged. The native [frozen source manifest](ui-menu-r1-source-manifest.json) and [pre-import manifest](ui-menu-r1-source-before-import.json) identify r1 separately. The acceptance report records the later Bootstrap/menu changes that its screenshots do not cover.

Representative r1 captures: [main menu](NativeR1/campaign/captures/01-cold-menu.png), [masked Settings](NativeR1/campaign/captures/05-settings-masked-input.png), [desktop entry](NativeR1/campaign/captures/08-enter-desktop.png), [repair connection](NativeR1/campaign/captures/11-repair-connect.png), [paid rent](NativeR1/campaign/captures/17-wallet-rent-paid.png), and [return to first person](NativeR1/campaign/captures/22-stand-first-person.png). The acceptance report lists and hashes all 30 captures and four player logs.

Live direct OpenAI connection/dialogue remains **unverified**. Historical relay tests or an older relay live smoke test do not validate the new direct provider. Windows runtime, audio output, target-hardware performance and graphical Editor Play Mode are also outside these results. Native logs retain the observed FMOD/audio-device initialization failures; no audio success is claimed.

[retained-files.json](retained-files.json) records an explicit 79-file copy allowlist, original locations, byte counts and SHA-256 hashes. Reports/logs are retained unchanged, including original workspace paths. Only the named reports, manifests, logs, confirmed-input timing record and captures were copied: no player `Game` directory, runtime `UserData`, campaign fixture, key settings file, cache or credential was included. The two Unity logs and source manifests sit beside their result reports; the [r1 build log](linux-ui-menu-r1-build.log), [r2 Windows build log](windows-ui-menu-r2-build.log) and [r2 Linux build log](linux-ui-menu-r2-build.log) are retained separately. A bounded scan found no key-shaped values or credential assignments in retained JSON/logs; the masked-input captures were also inspected. This is not a general security certification.
